# Cross-framework fixture

A roblox-ts project that depends on **both** Lucide packages at once.

```bash
pnpm --filter rbxts-svg-example-cross-framework run build
```

It is not a showcase — `examples/react` and `examples/vide` are. This exists to
prove one property that neither of them can, because neither has both packages
installed:

```text
@rbxts/lucide-react   Search  ─┐
                               ├─▶  same IR, same hash  ─▶  one raster
@rbxts/lucide-vide    Search  ─┘
```

There is deliberately no shared `@rbxts/lucide` data package, so each of the two
embeds its own copy of every icon's compiled bytes. The copies are identical, an
asset's cache identity is its content hash, and neither the package name nor the
framework appears in the render cache's key — so a game using both gets one
`EditableImage` per icon and size, not two.

Sync with Rojo, press Play, and read the output line:

```text
[lucide cross-framework] entries=1 references=3 hits=2 misses=1
```

Three labels — two React, one Vide, three different colours — one cache entry
and one rasterization.

The same invariant is asserted without Studio in `tests/luau/vide.luau` (two
separately decoded assets, one cache entry) and in `tests/integration/lucide.test.ts`
(identical generated bytes for every icon in both packages).
